### GeoWeb 项目常见技术问答（面试向）

1) 问：你在本项目中负责了哪些工作？与算法代码的关系是什么？
答：我负责 Web 端工程化与集成，包括前端交互、后端 API 网关/文件上传、与 FastAPI 计算微服务的通信协议、进度监控与可视化工作流设计。Python 科学计算与可视化核心算法来自课题组既有项目，非我编写。

2) 问：整体架构如何设计？为什么既要后端又要 Python 微服务？
答：架构分三层：前端（Vue3 + Vite）、后端（Spring Boot WebFlux）、计算微服务（FastAPI）。后端作为统一入口可做鉴权、限流、审计、用户模块与跨语言编排；长耗时计算直接命中 Python 服务能减少一次 hop 与序列化，加快进度反馈。

3) 问：前端如何与服务端交互？为何既有代理又有直连 8000？
答：开发环境通过 Vite 代理将 `/api`、`/user` 指向 8081；但异步计算启动与进度查询走 `http://localhost:8000` 是为了降低延迟与减少转发；最终版可统一走网关或在 Nginx 层反代 8000。

4) 问：长耗时任务的用户体验如何保证？
答：采用“异步启动 + 进度轮询（或WS） + 结果获取 + 下载”的协议；前端 `ProgressMonitor` 组件按 2s 轮询并对非百分比阶段（Loading/Saving）做节流与去噪，确保既有实时感又不过度刷屏。

5) 问：为什么后端选 WebFlux？
答：WebFlux 的非阻塞模型更适合做文件上传转发、大响应体、与外部服务（FastAPI）的 I/O 交互，可减少线程占用并提升吞吐；同时保留了代码可读性（通过 `WebClient`）。

6) 问：文件上传如何做大文件支持与错误处理？
答：后端放宽 `spring.servlet.multipart.*` 至 500MB，并调大 WebClient 缓冲；在 Python 端按需落盘到临时目录，分阶段处理并在异常时清理；对超限、CSV 格式、权限/IO 等错误做分类返回。

7) 问：可视化为什么要设计“预览/最终质量”两级？
答：预览用于滑动窗口时快速响应（降采样或轻量渲染），释放后再请求最终质量图，兼顾交互流畅与图像清晰度，减少不必要的重算开销。

8) 问：如何保证前后端对参数与文件的一致理解？
答：约定表单字段名（`tt_file/wtt_file/mask_file`、`rp/vf/wtt/beta`、`session_id`、`lenZ/dz` 等），统一在后端转发层与 FastAPI 接口中复用同名键；并通过演示数据路径做默认值与回退逻辑。

9) 问：进度是如何上报与消费的？
答：Python 计算在内部回调中更新 `progress_messages[session_id]`，前端通过 `GET /borehole/progress/{id}` 轮询；同时提供 `WS /ws/progress/{id}` 以支持实时推送，便于以后切换为 WebSocket。

10) 问：为什么部分下载链接是绝对地址（指向 8000）？
答：下载是静态文件直出，走计算微服务可避免再次转发与重复序列化；生产可改为统一网关地址或 CDN 分发。

11) 问：数据库的作用与可选性？
答：目前仅用于基础用户模块（注册/登录/列表），不涉及计算主流程；本地演示可跳过或改为 H2。生产中可扩展为任务/审计/配额等。

12) 问：如何在生产部署？
答：建议三进程或容器化：Nginx/Ingress 统一入口（反代 8081 与 8000），后端 Spring Boot（8081），FastAPI（8000）。开启 HTTPS、鉴权（JWT/OAuth2）、跨域白名单、上传大小与并发限制，并将中间结果输出至持久化存储。

13) 问：安全性考虑？
答：开发态开放 CORS；生产应：限定 `allow_origins`、启用鉴权、限制文件类型/大小/频率，隔离临时目录、清理策略，敏感配置走环境变量。

14) 问：你的工程化贡献体现在哪里？
答：接口协议抽象、网关化转发、异步进度可观测、前端 UX（预览/最终、滑条窗口）、错误边界与回退、启动指引与演示模式、可移植的配置与代理策略。

15) 问：如果要扩展新的算法任务，怎么做？
答：在 FastAPI 新增端点并复用异步/进度框架；在后端新增转发方法与参数映射；前端添加表单与可视化组件，遵循相同的“启动-进度-结果-下载”工作流即可。
